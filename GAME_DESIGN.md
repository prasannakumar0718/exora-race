# Lane Rush — Game Design & Authoritative Multiplayer Architecture

## 1. Core Game Loop & Gameplay Mechanics

Lane Rush is an arcade lane racer where drivers navigate high-speed traffic across three distinct road lanes (`LANES = [340, 480, 620]`).

### Dynamics & Difficulty Progression
- **Base Road Speed:** 420 px/s
- **Speed Ramp:** Increases linearly by 4.5 px/s² up to a maximum boost of +380 px/s (top speed = 800 px/s).
- **Distance Scoring:** Score accumulates continuously based on elapsed driving duration: `dt * (10 + min(25, elapsed * 0.18))`.
- **Near Miss / Passed Car Bonus:** +5 points awarded whenever a traffic vehicle passes below `CAR_Y + 50`.
- **Coins:** Shared coin pickups spawn periodically (single or triplet trails) at road speed. Collecting a coin awards +75 score and increments the player's coin tally.
- **Collisions:** Overlapping bounding boxes with trucks (`72x108`) or cars (`60x94`) causes a crash, triggering particles, screen shake, and disabling active driving status.

## 2. Server-Authoritative Multiplayer Architecture

### Authoritative Responsibility
The Node.js backend (`server.js`) owns the single source of truth for all competitive racing data:
1. **World Clock & Position Progression:** Road offset, world speed, and delta calculations are computed exclusively on the server at 20 Hz (50 ms ticks).
2. **Deterministic Entity Generation:** Obstacle vehicles and coins are procedurally generated by the server with unique IDs, lanes, and speeds.
3. **Player Steering Validation:** Clients send directional intention (`{ type: 'input', direction: -1 | 1 }`). The server validates the direction, clamps the lane to `[0, 2]`, and enforces an input cooldown of 65 ms.
4. **Collision & Coin Adjudication:** The server tests collisions against its authoritative positions. Clients cannot claim coin pickups or report artificial safety.
5. **Fair Coin Collection:** Shared coins store `collectedBy = [slot1, slot2]`. Each driver can collect a coin once, preventing host-order pickup bias while ensuring coins disappear locally once picked up.
6. **Race Outcome & Rematch:** The race concludes when all drivers have crashed or expired. The driver with the highest score wins (or a tie is declared). Rematches require mutual consent from both drivers.

### Client Prediction & Visual Interpolation
To eliminate input lag across network latencies without compromising authority:
- **Local Client Prediction:** Upon keypress or touch gesture, the local client immediately predicts `player.targetX` and smoothly slides the vehicle toward the target lane. Authoritative snapshots from the server continuously reconcile the true lane.
- **Rival Vehicle Smoothing:** Rival drivers are rendered with lerp interpolation (`remotePlayer.x += (remotePlayer.targetX - remotePlayer.x) * dt * 13`) rather than jumping abruptly between lanes.
- **Dead-Reckoning Extrapolation:** Between server snapshots, traffic vehicles and coins move forward using the authoritative world speed. When the race is paused or frozen, dead-reckoning is strictly suspended to prevent drift.

## 3. Disconnection & Reconnection State Machine

```
[ WAITING ] --(Player 2 Joins)--> [ COUNTDOWN (3s) ] --> [ RACING ]
     |                                                        |
(P1 drops)                                               (Any driver drops)
     v                                                        v
[ WAITING ] <--(Valid Token Reconnect)-- [ RECONNECTING (45s) ]
(Host slot reserved)                                          |
                                                    (45s window expires)
                                                              v
                                                     [ FINISHED / OUT ]
```

1. **Session Authentication:** Upon joining or creating a room, each driver receives a 24-byte cryptographically secure session token (`crypto.randomBytes`). Room codes are public, but only holders of the matching session token can reclaim a player slot.
2. **Race Freeze:** If any driver disconnects during countdown or active racing, the server instantly freezes world simulation, pausing traffic and coin progression.
3. **Reconnection Window:** A 45-second grace window (`RECONNECT_GRACE_MS`) begins. The remaining connected driver observes a pause banner displaying the exact countdown time remaining.
4. **Resumption:**
   - If the disconnected driver reconnects with their valid token, the server restores their exact slot, lane, and score, gives a 3-second countdown notice, and resumes the race.
   - If the player refreshed their page rapidly while their previous TCP connection was still closing, the server seamlessly replaces the old socket with the new connection without rejecting the reconnect.
5. **Expiration:** If the 45-second window expires without reconnection, the absent driver is marked `expired = true; active = false`. If the other driver is still alive, the race resumes solo for that driver to finish their run. If both drivers are inactive, the race terminates with final scores.

## 4. Connection State Mapping

The UI displays distinct real-time badge states:
- `Connecting`: WebSocket handshake or reconnect attempt in progress.
- `Connected`: Room active and communication healthy.
- `Reconnecting`: Socket interrupted; client trying to reconnect or waiting for disconnected rival within 45s.
- `Connection Lost`: Grace period expired or server unreachable.
- `Race Finished`: Final scores calculated and winner determined.

## 5. Security & Anti-Abuse Controls

- **Payload Size Capping:** Strict 4 KB message limit prevents memory exhaustion attacks (RFC 6455 opcode 1009).
- **Sliding-Window Rate Limiting:** Max 35 messages/sec with burst protection prevents CPU flooding. Sockets exceeding limits are throttled or terminated with code 1008.
- **CSWSH Origin Verification:** WebSocket upgrade requests validate the `Origin` header against configured `ALLOWED_ORIGINS`.
- **Proactive Heartbeat:** 15-second ping/pong cycles detect half-open TCP connections from mobile sleep or network loss.
- **Sanitized Room Codes:** 6-character alphanumeric uppercase codes with collision resistance.
